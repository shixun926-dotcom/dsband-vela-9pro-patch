## 这个仓库为什么存在

DSBand 原版 v0.2.0 在小米手环 9 Pro 上有一个实际影响使用的问题：**应用没有可用的退出方式**。

原版设计里，退出依靠「在第一屏右滑」，但这段代码在真机上是失效的：

1. 取触点坐标写的是 `evt.touches || evt.changedTouches`。抬手（`touchend`）时 `touches` 是**空数组**，而空数组在 JavaScript 里是 truthy，于是永远取不到触点、返回 `-1`，位移计算出负数，退出判断不可能成立。
2. 就算判断成立，退出调用的是 `router.back()`。而原作者自己在后续提交的注释里写明「pro/9：系统右滑返回不可用」——在手环 9 Pro 上这个调用退不出去。

结果就是：装到手环上以后，**进了应用出不来**。

本仓库在此基础上做了修复和增强。原作者的后续 master 分支也有相关改动（提交 `762e559「为9pro/10pro/miband9添加返回按钮」`），但**至今没有发布新的 Release**，所以无法通过官方渠道安装到修复后的版本。

## 改动内容

### 1. 新增左上角「返回」按钮

- 位置：屏幕左上角常驻（三屏都可见），半透明胶囊 + `<` 箭头 + 返回文案
- 行为：点击调用 `$app.exit()`，直接退出快应用回到表盘
- 涉及文件：`src/pages/dashboard/dashboard.ux`、`src/pages/dashboard/dashboard.css`、`src/i18n/{default,en,zh-CN}.json`

### 2. 修复并扩展右滑退出

| 改动 | 原版 | 本仓库 |
|---|---|---|
| 触点取值 | `touches \|\| changedTouches` | `changedTouches \|\| touches` |
| 生效范围 | 仅第一屏（`swipeIndex === 0`） | **任意界面（第 1/2/3 屏）** |
| 触发阈值 | `dx > 125` 且 `\|dy\| <= 50` | `dx > 40` 且 `dx > \|dy\|` |
| 退出方式 | `router.back()` | `$app.exit()` |
| 事件绑定位置 | 仅 `.page` | `.page` + 3 个 `.panel` + 2 个 `<scroll>`，并同时监听 `touchend` / `touchcancel` |

**副作用（已知且接受）**：右滑现在在任何一屏都是退出，因此**无法再从第二屏右滑回到第一屏、从第三屏右滑回到第二屏**。左滑翻页不受影响，仍可正常切换三屏。

## 构建

```powershell
npm install
npx aiot build
```

构建产物在 `dist/` 下。工具链：`aiot-toolkit 2.0.5`（原项目 `package.json` 中声明）。

如遇 `npm install` 生命周期脚本报 `spawn EPERM`（受限环境常见），可用 `npm install --ignore-scripts`，构建本身不依赖那两个脚本。

## 已知限制

- **未在真机验证。** 本仓库的改动是在没有小米手环实机的情况下完成的，只保证代码逻辑正确、编译产物中包含相应绑定与逻辑。右滑手势能否生效还取决于 Vela 的 `swiper` / `scroll` 组件在原生层是否吞掉了触摸事件——如果这一层拦截成立，页面上的任何 JS 触摸回调都收不到，右滑仍然不会生效（此时左上角按钮仍可用）。
- 右滑退出的阈值（40px）与「横向位移占优」判定是按可用性权衡设定的，未在真机上做手感调优。纵向滚动内容时不会触发退出。
- 左滑翻页依赖原版的 `<swiper>` 实现，未做改动。
